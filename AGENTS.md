# NeuroX repository instructions

These instructions apply to the whole repository. A closer `AGENTS.md`
overrides them for its subtree; `apps/web/AGENTS.md` contains mandatory Next.js
guidance.

## Work efficiently

1. Start with `git status --short`, then read only the relevant sections of
   `CURRENT_STATUS.md`, `MASTER_TODO.md`, and the files involved in the task.
2. Use `rg` and bounded `sed`/`nl` ranges. Do not dump large files, generated
   clients, lockfiles, or full logs into context.
3. Batch independent read-only inspections and run the smallest relevant test
   first. Expand verification only in proportion to the change.
4. Reuse existing domain types, services, scripts, fixtures, and generated
   contracts. Do not create a parallel implementation for an existing concern.
5. Keep user updates and the final handoff concise: outcome, evidence, remaining
   blocker. Do not narrate routine commands.
6. Preserve the dirty worktree. Never discard, overwrite, stage, commit, push,
   or reformat unrelated user changes unless explicitly requested.

## Source-of-truth map

- `services/api/app/domain/`: pure rules and calculations.
- `services/api/app/services/`: application orchestration and persistence-facing
  services.
- `services/api/app/routers/`: authorized HTTP boundaries; keep business rules
  out of routers.
- `services/api/app/workers/`: durable event consumers and workflow execution.
- `services/api/app/models.py`: SQLAlchemy persistence model.
- `services/api/app/schemas.py`: public API contracts.
- `services/api/alembic/versions/`: immutable migration history; add a new
  revision instead of editing an applied one.
- `apps/web/`: Next.js UI. Read `apps/web/AGENTS.md` before editing it.
- `apps/web/src/generated/`: generated by Orval; do not hand-edit.
- `packages/contracts/openapi.json`: generated from FastAPI.
- `packages/contracts/events/`: versioned event contracts.
- `docker-compose.yml`: complete functional product profile.
- `docker-compose.operations.yml`: optional telemetry and backup overlay.
- `RUN_PROJECT.md`: supported cross-platform run and test commands.
- `CURRENT_STATUS.md`: evidence-backed implementation state.
- `MASTER_TODO.md`: remaining acceptance and release gates.

## Architecture invariants

- PostgreSQL is authoritative. Redis and Qdrant are derived and must fail
  without corrupting workflow truth.
- Every tenant-owned query, mutation, event, cache key, alert, model, object,
  and aggregate must be tenant-scoped. Preserve PostgreSQL RLS and
  transaction-local tenant context.
- Use transactional outbox/inbox delivery, versioned event contracts,
  idempotency keys, manual acknowledgements, bounded retries, and DLQs.
- Human resume, approval, review, and ERP actions remain case-version and
  evidence-hash bound. Preserve segregation of duties.
- Deterministic duplicate, sanctions, bank-change, PO/GRN, arithmetic, policy,
  and OPA controls are authoritative and fail closed.
- ML findings are explainable `SHADOW`/review signals. They cannot approve,
  reject, pay, change vendor data, lower severity, or clear a deterministic
  hold.
- LLM output may summarize or classify evidence but cannot authorize a workflow
  transition. Never execute LLM-generated SQL; use allowlisted typed queries.
- Raw documents, OCR text, bank data, tax identifiers, credentials, signed
  URLs, prompts, and chain-of-thought must not enter logs, traces, events, or
  external model payloads.
- Current OCR is local: native PDF, Docling, Tesseract, then EasyOCR. Cloud OCR
  is not implemented. Add it only behind a provider interface, tenant policy,
  explicit data-egress approval, circuit breaker, cost controls, and tested
  local/cloud fallback.
- External Gemini calls default off and are limited to synthetic or approved
  tokenized data. Provider failure must remain visible and preserve mandatory
  deterministic work.
- SMTP and observability failures must not change case state. ERP writes require
  an independent, current OPA decision and idempotent evidence-bound request.

## Change discipline

- Make the smallest coherent change that satisfies the request.
- Prefer pure domain functions and typed contracts. Keep I/O at adapters.
- Validate all external inputs and normalize at the boundary.
- Add or update tests with every behavior change, including denied and failure
  paths.
- Never weaken a security control to make a test pass.
- Never introduce placeholder production credentials, real business data, or
  secrets into source, fixtures, output, screenshots, or chat.
- Do not add infrastructure merely because it is popular. Extend the existing
  PostgreSQL, RabbitMQ, MinIO, Qdrant, Redis, Keycloak, OPA, Gemini, Recharts,
  and worker boundaries unless the task proves a missing capability.
- Preserve historical Alembic revisions. A schema change requires one new
  reversible revision, tenant/RLS checks, and matching ORM/API changes.
- Change FastAPI schemas first, export OpenAPI, then regenerate Orval. Do not
  patch generated TypeScript models manually.
- Use `apply_patch` for hand edits. Formatting or generator commands may update
  files mechanically.

## Verification ladder

Run the smallest applicable level, then broader levels when risk warrants it.

### Backend

```bash
cd services/api
.venv/bin/ruff check app tests scripts ../mock_erp
.venv/bin/mypy --ignore-missing-imports app/domain
.venv/bin/pytest -q tests/RELEVANT_TEST.py
.venv/bin/pytest -q
```

### Frontend

```bash
cd apps/web
npm run lint
npx tsc --noEmit
npm run build
```

### Contracts

```bash
cd services/api
.venv/bin/python -m scripts.export_openapi
cd ../../apps/web
npm run api:generate
```

Inspect generated diffs and ensure they reflect only the intended schema
change.

### Compose and shell

```bash
docker compose config --quiet
bash -n scripts/bootstrap-local-env.sh scripts/stack.sh
```

### Full product

```bash
./scripts/stack.sh product-up
./scripts/stack.sh status
curl --fail --silent --show-error http://localhost:8000/health/live
curl --fail --silent --show-error http://localhost:8000/health/ready
```

Use only the checked-in synthetic corpus. Follow `RUN_PROJECT.md` for
cross-platform setup, manual journeys, troubleshooting, shutdown, and the
destructive-reset warning.

## Evidence and documentation

- `IMPLEMENTED` means code exists and focused checks pass.
- `VERIFIED` requires the named live, browser, security, numerical, or failure
  evidence.
- `BLOCKED` must state the exact external condition and the checks already
  attempted.
- Update `CURRENT_STATUS.md` and `MASTER_TODO.md` only when evidence changes.
  Never mark a live, E2E, security, load, backup, or production gate complete
  from unit tests alone.

## Completion checklist

- Requested behavior and failure paths are implemented.
- Tenant isolation, authorization, idempotency, audit, PII, and human-control
  boundaries remain intact.
- Relevant tests pass; generated contracts and migrations are synchronized.
- No unrelated changes, secrets, real data, or misleading status claims were
  introduced.
- The handoff names tests run, tests not run, and any remaining external
  prerequisite.
